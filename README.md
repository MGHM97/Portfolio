# mateusvieira.dev

Personal site and portfolio of **Mateus Vieira**, Senior Front-end Engineer building accessible, AI-powered interfaces.

## Stack

- [Astro](https://astro.build) — static output, zero client JS except a tiny theme toggle
- TypeScript in `strictest` mode
- Plain CSS with custom properties (light/dark themes)
- Static i18n in five languages with typed dictionaries
- Playwright + axe-core for end-to-end and WCAG 2.2 AA checks on desktop and mobile, in every locale
- Content Security Policy with hashed inline scripts and styles
- Markdown articles with build-time Prism highlighting (no inline styles, so it works under the CSP)
- GitHub Actions for formatting, type checks, build and tests

## Getting started

```sh
yarn install
yarn dev          # http://localhost:4321
yarn build        # type check + production build
yarn test:e2e     # runs against the production build
```

## Internationalization

The site ships in English (default, at `/`), Spanish (`/es/`), French (`/fr/`), German (`/de/`) and Brazilian Portuguese (`/pt-br/`). Every locale is a static page with its own `<html lang>`, canonical URL, `hreflang` alternates and sitemap entry. No JavaScript is involved in switching languages.

- **UI copy** lives in [`src/i18n/locales/`](src/i18n/locales). Each dictionary is typed against the English one, so a missing translation fails `astro check` and the build.
- **Locale-independent data** (name, links, companies, dates, skills) lives in [`src/data/profile.ts`](src/data/profile.ts).
- **Case studies and articles** live in `src/content/work/<locale>/` and `src/content/posts/<locale>/`. English is the source of truth; when a translation is missing, the English version is shown with a notice, marked `lang="en-US"` and canonicalized to the English URL.
- **Tests** run accessibility, layout and `hreflang` checks for every locale.

To add a string, add it to the `Dictionary` type in `en.ts`; TypeScript then points at every locale that still needs it.

## Social preview images

`public/og/<locale>.png` are generated from the dictionaries with the site's own fonts:

```sh
yarn og   # builds the site, then renders one 1200×630 image per locale
```

Run it whenever the hero role, headline or availability changes, and commit the images.

## Deployment

The site is static and deploys to Vercel with the settings in [`vercel.json`](vercel.json): security headers, long-lived caching for hashed assets, and trailing slashes.

- `SITE_URL` sets the canonical origin (e.g. `https://mateusvieira.dev`). Without it, builds on Vercel fall back to the project's production URL, so canonical links, `hreflang` and the sitemap always point to a real address.
- Pages ship a Content Security Policy generated by Astro, with hashes for every inline script and style; `frame-ancestors` is sent as a header because it can't live in a `<meta>` tag.
- End-to-end tests run on port 4400 against the production build, so they never pick up a local `yarn dev`.
